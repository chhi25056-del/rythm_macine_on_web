Webリズムマシン（ステップシーケンサー）コード構造と処理フロー解説書
================================================================================

本ドキュメントは、Next.js (React) + Web Audio API で構築されたWebリズムマシン
（ステップシーケンサー）の全体構造、状態管理、音声再生ロジック、主要な関数と
実行フローを網羅的に解説したものです。

1. 全体構造と役割分担（ファイル・コンポーネント構成）
================================================================================

このプロジェクトは、関心事の分離（UI表示、純粋な音楽ロジック、オーディオ合成、
エクスポート）が徹底されたクリーンなモジュール構造になっています。

【レイヤー別ファイル構成】

● [UI・統合コントロール層]
・src/app/page.tsx
  - アプリケーションのエントリーポイント。画面中央に RhythmMachine を配置します。
・src/components/RhythmMachine.tsx
  - アプリケーションの「心臓部」。シーケンサー全体のUI、再生タイマー、状態の集約、
    ユーザー操作ハンドラー、各サブコンポーネントの配置を一括で制御します。

● [シーケンサー純粋ロジック層]（ReactやAudioContextに依存しない純粋関数）
・src/lib/sequencer.ts
  - パターンデータの型定義（Pattern, TrackId, TimeSignature 等）。
  - ステップの反転、ポリメーター計算（トラックごとの長さに応じた発音判定）、
    小節のコピー、クイックフィル、小節数拡張時の自動ループ複製など、
    状態の更新・計算を行う「純粋関数（副作用のない関数）」がまとまっています。

● [オーディオ生成・合成層]
・src/lib/synthAudio.ts
  - Web Audio APIを用いた内蔵ドラム（Kick, Snare, HiHats, Toms, Crash）の
    シンセサイザー合成ロジック。
  - `BaseAudioContext` を受け取る設計になっており、ブラウザでのリアルタイム再生
    （AudioContext）とWAV書き出し（OfflineAudioContext）で全く同一の音を鳴らします。
・src/lib/customAudio.ts
  - ユーザーがPCからアップロードした音声ファイル（WAV, MP3等）のバリデーション、
    AudioBufferへのデコード、独立した再生・消音（チョーク）ユーティリティ。
・src/components/CustomTrackControl.tsx
  - カスタムトラックの音声ファイル選択、削除、試聴プレビューを行うUI部品。

● [ファイルエクスポート層]
・src/lib/wavExport.ts
  - `OfflineAudioContext` を使って全小節を数ミリ秒〜数十ミリ秒でオフラインレンダリングし、
    16-bit PCM WAV (RIFF WAVE) フォーマットのバイナリ（Blob）を生成してダウンロード。
・src/lib/midiExport.ts
  - General MIDI (Channel 10) 規格の Standard MIDI File (Format 0) バイナリを
    TypeScriptだけでゼロから構築。テンポ・拍子記号・ポリメーターを反映した .mid を出力。
・src/components/ExportMenu.tsx
  - コントロールバーの「書き出し ▼」ボタンとドロップダウンメニュー、レンダリング中
    のローディング状態、完了トースト通知のUI。

● [チュートリアル・学習システム層]
・src/lib/tutorial.ts / src/hooks/useTutorial.ts / src/components/TutorialSpotlight.tsx
  - 基本操作チュートリアル（再生、ステップ打ち込み、BPM変更、フィルイン、ポリメーター）。
・src/lib/patternTutorial.ts / src/hooks/usePatternTutorial.ts / 
  src/components/PatternTutorialMenu.tsx / src/components/PatternTutorialGuide.tsx
  - 8ビートや4つ打ちなどの名曲リズムパターンを学べるオプトイン式学習チュートリアル。

2. 状態管理（State）の動きとデータフロー
================================================================================

シーケンサーの動作は、React の `useState` と `useRef` を組み合わせた
「単方向データフロー（Unidirectional Data Flow）」で管理されています。

--------------------------------------------------------------------------------
(1) 主要な State（状態）の一覧
--------------------------------------------------------------------------------
1. `pattern`: Record<TrackId, boolean[]>
   - 各トラック（kick, snare等 + custom1〜4）ごとのON/OFF状態（全80ステップ分の真偽値配列）。
2. `isPlaying`: boolean
   - 再生中（true）か停止中（false）か。
3. `globalStep`: number
   - 再生開始からの累積ステップ数（0, 1, 2, 3, ...）。
4. `bpm`: number
   - テンポ（デフォルト: 120、範囲: 60〜200）。
5. `bars`: MeasureCount (1 | 2 | 4)
   - ループ全体の小節数。
6. `timeSignature`: TimeSignature ("4/4" | "3/4" | "5/4" | "6/8" | "7/8")
   - 現在の拍子設定（1小節のステップ数や拍の区切り）。
7. `trackLengths`: Record<TrackId, number>
   - トラックごとのステップ長（ポリメーター設定。初期値は16など小節長と同一）。
8. `activeBar`: number
   - 現在画面上で編集対象として表示している小節番号（0〜3）。

--------------------------------------------------------------------------------
(2) State更新と再レンダリングの流れ
--------------------------------------------------------------------------------
■ 例1: ユーザーがステップボタンをクリックしてONにした場合
1. ユーザーがグリッド上のステップをクリックします。
2. クリックイベントから `toggleStep(trackId, stepIndex)` が呼び出されます。
3. `togglePatternStep` 純粋関数が呼ばれます：
   - 既存の `pattern` オブジェクトを直接変更（ミューテート）せず、
     該当トラックの配列の該当インデックスのみを反転（!val）させた
     「新しいオブジェクト（イミュータブルコピー）」を生成します。
4. `setPattern(newPattern)` が実行されます。
5. React が State の変更を検知し、該当のステップボタンのみが再レンダリングされ、
   色（アクセントカラー）と中央の光るドットが即座に点灯します。
6. ※ 停止中の場合、ユーザーへのフィードバックとして `triggerInstrument(trackId)` が呼ばれ、
   その打楽器のプレビュー音が「ポン」と1回鳴ります。

■ 例2: ユーザーが「PLAY / STOP」ボタンを押した場合
1. `togglePlay()` が実行されます。
2. もし停止中（`!isPlaying`）なら：
   - ブラウザの Web Audio API はユーザー操作（ジェスチャー）がないと音を鳴らせない制約
     があるため、ここで `getAudioContext()` を呼び出して `ctx.resume()` を行います。
   - `globalStepRef.current = 0` とリセットします。
   - `setGlobalStep(0)` を行い、画面の再生ヘッドを先頭に戻します。
   - 0番目のステップ音を即座に `triggerStepSounds(0)` で発音します。
   - `setIsPlaying(true)` に更新します。
   - 後述の `useEffect` タイマーが起動し、自動ループが始まります。
3. もし再生中なら：
   - `setIsPlaying(false)` に更新します。
   - タイマーのクリーンアップ関数が自動的に走り、`clearInterval` されます。
   - カスタムサンプルの残響音源を即座に消音（チョーク）します。

3. 音声再生ロジックとタイマー処理の連動関係
================================================================================

「タイマーによるステップの進行」と「Web Audio API による発音」がどのように
連携しているかを解説します。

--------------------------------------------------------------------------------
(1) テンポ（BPM）とタイマー周期の計算式
--------------------------------------------------------------------------------
シーケンサーの1ステップは通常「16分音符」に相当します。
- 1分間 = 60,000 ミリ秒
- 1分間に BPM 回の四分音符（4拍）があるため、四分音符1拍の長さは `60,000 / BPM` (ms)
- 1ステップは四分音符の 1/4（16分音符）なので：
  `ステップ周期 (ms) = (60,000 / BPM) / 4 = 15,000 / BPM`

例:
- BPM = 120 のとき: 15,000 / 120 = 125 ミリ秒ごとに次のステップへ進む
- BPM = 60 のとき: 15,000 / 60 = 250 ミリ秒

--------------------------------------------------------------------------------
(2) タイマー（setInterval）と ref による高速処理
--------------------------------------------------------------------------------
React の State (`pattern`, `trackLengths`, `globalStep`) は非同期に更新されるため、
`setInterval` のコールバック関数の中で古い State（Stale Closure）を参照してしまう問題があります。
これを防ぐため、本アプリでは **Ref（参照）との二重同期パターン** を採用しています：
- `patternRef.current = pattern;` （useEffectで常に最新のパターンを同期）
- `trackLengthsRef.current = trackLengths;` （最新のトラック長を同期）
- `globalStepRef.current = tick;` （タイマーが毎ミリ秒更新）

■ 再生ループの1サイクル（1ステップ進むごとの実行順序）:
1. `setInterval` のタイマーが発火（例: 125ms ごと）。
2. `nextTick = globalStepRef.current + 1` と内部カウンタをインクリメント。
3. `triggerStepSounds(nextTick)` を呼び出し、そのステップで鳴るべき音を判定・発音。
4. `setGlobalStep(nextTick)` で React の画面を更新（現在ステップの枠線が黄色く点灯）。
5. `autoFollow` が有効なら、再生小節が切り替わったときに自動で表示小節（activeBar）を切り替え。

--------------------------------------------------------------------------------
(3) ポリメーター（Polymeter）の発音判定ロジック
--------------------------------------------------------------------------------
一般的なドラムマシンは全トラックが同じ16ステップでループしますが、本アプリは
トラックごとにステップ長（例: ハイハットだけ7ステップ、キックは16ステップ等）を
自由に変更できる「ポリメーター」に対応しています。

発音判定（`shouldTriggerTrack`）の流れ：
1. グローバルステップ番号 `globalStep`（例: 17ステップ目）を受け取ります。
2. 該当トラックのステップ長 `trackLength`（例: 7）で剰余を計算します：
   `stepIdx = globalStep % trackLength`  （17 % 7 = 3 ➔ 3番目のステップ）
3. `pattern[trackId][stepIdx]` が `true` かどうかをチェック。
4. `true` ならばその瞬間に発音！
これによって、全体の小節ループとは独立して、各トラックの位相がズレていく
複雑で現代的なポリリズム・ミニマルグルーヴが自動生成されます。

--------------------------------------------------------------------------------
(4) Web Audio API によるシンセサイザー合成の仕組み
--------------------------------------------------------------------------------
外部の重い音声ファイルをダウンロードするのではなく、ブラウザの内蔵オシレーター
（発振器）とノイズジェネレーターを組み合わせてドラムの音をリアルタイム合成しています。

1. バスドラム（Kick）:
   - オシレーター（サイン波）の周波数を 150Hz から 0.01Hz へ 0.15秒で急降下（ピッチベンド）。
   - 音量（GainNode）も 1.0 から 0.01 へ指数関数カーブで急減衰。
   - 「ドスッ」というパンチのあるアタックと低域の余韻を作ります。

2. スネアドラム（Snare）:
   - 三角波オシレーター（180Hz ➔ 40Hz, 0.1秒）で「太鼓の胴鳴り」を作成。
   - 同時に、ホワイトノイズを 1200Hz のハイパスフィルターに通して
     スナッピー（裏面の響き線）の「ザッ」というノイズを合成してミックス。

3. ハイハット（Hi-Hat Closed / Open）:
   - ホワイトノイズに 7500Hz（クローズド）または 6500Hz（オープン）の高域ハイパスフィルター
     をかけ、金属的な擦過音を抽出。
   - クローズドは 0.05秒の極短エンベロープで「チッ」、オープンは 0.35秒の長めのエンベロープで
     「シャーン」と減衰させます。

4. クラッシュシンバル（Crash）:
   - 6200Hz のハイパスフィルターを通したホワイトノイズに 0.9秒のロングサステインエンベロープ
     を適用し、抜けの良い明るいシンバル音を生成。

4. 主要な関数・処理の解剖（入力・処理・出力）
================================================================================

コードを読み解く上で中心となる 8 つの重要関数を解剖します。

--------------------------------------------------------------------------------
① togglePatternStep (src/lib/sequencer.ts)
--------------------------------------------------------------------------------
【入力】
  - pattern: Pattern （現在の全トラックのステップ状態）
  - trackId: TrackId （反転させたいトラックの名前。例: "kick"）
  - stepIndex: number （反転させたいステップ番号。例: 0）
【処理】
  - 指定されたトラックの配列のみを取り出し、stepIndex の要素を true ➔ false または false ➔ true に反転。
  - イミュータブルに新しい Pattern オブジェクトを構築。
【出力】
  - 新しい Pattern オブジェクト（React の setPattern に渡す用）。

--------------------------------------------------------------------------------
② expandPatternMeasures (src/lib/sequencer.ts)
--------------------------------------------------------------------------------
【入力】
  - pattern: Pattern （現在のパターン）
  - fromBars: MeasureCount （変更前の小節数: 1 または 2）
  - toBars: MeasureCount （変更後の小節数: 2 または 4）
  - stepsPerBar: number （1小節のステップ数: 16など）
【処理】
  - 小節数が拡張された際、新しく追加された小節（例: 3〜4小節目）に対して、
    既存の小節（1〜2小節目）のステップデータを数学的な剰余 `targetBar % fromBars` で
    ループ複製します。
【出力】
  - 後続小節にパターンがコピーされた新しい Pattern オブジェクト。

--------------------------------------------------------------------------------
③ shouldTriggerTrack (src/lib/sequencer.ts)
--------------------------------------------------------------------------------
【入力】
  - pattern: Pattern
  - trackId: TrackId
  - globalStep: number （再生開始からの通算ステップ番号）
  - trackLength: number （そのトラックのループステップ数）
【処理】
  - `(globalStep % trackLength)` で該当トラックにおける現在位置を算出。
  - パターンのその位置が true になっているかを boolean で返す。
【出力】
  - boolean （true: 発音する / false: 発音しない）

--------------------------------------------------------------------------------
④ triggerStepSounds (src/components/RhythmMachine.tsx)
--------------------------------------------------------------------------------
【入力】
  - tick: number （現在のステップ番号）
【処理】
  - 全トラック（内蔵ドラム 7 種 + カスタムトラック 4 種）をループ。
  - 各トラックについて `shouldTriggerTrack` を評価。
  - 条件を満たしたトラックに対して `playInstrument(trackId, ctx, now)` を実行。
【出力】
  - なし（Web Audio API のスピーカーへ直接発音命令をスケジューリングする副作用）。

--------------------------------------------------------------------------------
⑤ playBuiltinTrack (src/lib/synthAudio.ts)
--------------------------------------------------------------------------------
【入力】
  - trackId: BuiltinTrackId ("kick", "snare", "hihatClosed", etc.)
  - ctx: BaseAudioContext （AudioContext または OfflineAudioContext）
  - time: number （発音開始時刻）
  - noiseBuffer: AudioBuffer （スネアやハットで共用するホワイトノイズ波形）
【処理】
  - 指定の打楽器に応じたオシレーターやフィルターノードを生成・結線し、
    `time` のタイミングで `start(time)` / `stop(time + duration)` をスケジュール。
【出力】
  - なし（オーディオグラフにノードを接続）。

--------------------------------------------------------------------------------
⑥ renderPatternToWavBlob (src/lib/wavExport.ts)
--------------------------------------------------------------------------------
【入力】
  - options: RenderWavOptions （pattern, trackLengths, bpm, bars, timeSignature, customSamples）
【処理】
  - ブラウザの `OfflineAudioContext`（仮想オーディオ環境）を生成。
  - 全小節分のステップ発音イベントをミリ秒の狂いなくスケジュール。
  - `offlineCtx.startRendering()` を呼び出して一瞬で全波形をレンダリング。
  - レンダリングされた AudioBuffer から 16-bit PCM WAV (RIFF) のバイナリ配列を生成。
【出力】
  - Promise<Blob> （ファイルダウンロード可能な audio/wav 形式の Blob オブジェクト）。

--------------------------------------------------------------------------------
⑦ generateMidiFile (src/lib/midiExport.ts)
--------------------------------------------------------------------------------
【入力】
  - options: RenderMidiOptions
【処理】
  - 各ステップで発音される打楽器を General MIDI ドラム規格（Ch 10、Kick=36, Snare=38等）に変換。
  - Note On（音の開始）と Note Off（音の停止）イベントを作成し、時間軸（Tick）順に整列。
  - テンポ情報、拍子記号、可変長数値（VLQ）のデルタタイム、SMF Header/Track チャンクを
    純粋なバイト配列（Uint8Array）として結合。
【出力】
  - Uint8Array （DAWで即座に読み込める .mid ファイルの生バイナリ）。

--------------------------------------------------------------------------------
⑧ handleMeasureChange (src/components/RhythmMachine.tsx)
--------------------------------------------------------------------------------
【入力】
  - newBars: MeasureCount （ユーザーが選択した新しい小節数: 1, 2, 4）
【処理】
  - 以前の小節数より増えた場合、`expandPatternMeasures` を呼んでパターンを拡張コピー。
  - 全体長に設定されていた各トラックのポリメーター長を新しい小節の長さに合わせて延伸。
  - `setBars(newBars)` と `setPattern(newPattern)` を実行。
【出力】
  - なし（State を更新）。


================================================================================
5. ユーザー操作時の具体的な実行フローまとめ
================================================================================

--------------------------------------------------------------------------------
【フロー A: パターンを打ち込んで再生するまで】
--------------------------------------------------------------------------------
[ユーザーがキックの 1拍目（Step 0）をクリック]
   │
   ▼
[toggleStep("kick", 0) が呼ばれる]
   │
   ├──▶ togglePatternStep(pattern, "kick", 0) で pattern.kick[0] = true に
   ├──▶ setPattern(newPattern) ➔ 画面上のステップボタンが黄色く光る
   └──▶ triggerInstrument("kick") ➔ プレビューとしてキックの低音が「ドン」と1回鳴る
   │
[ユーザーが「PLAY」ボタンをクリック]
   │
   ▼
[togglePlay() が呼ばれる]
   │
   ├──▶ getAudioContext() ➔ ブラウザのオーディオエンジンを起動 (resume)
   ├──▶ globalStepRef.current = 0 ➔ 内部カウンタをゼロにリセット
   ├──▶ triggerStepSounds(0) ➔ 0ステップ目のキックが即座に鳴る
   ├──▶ setIsPlaying(true) ➔ ボタンが緑の「PLAY」からオレンジの「STOP」に変化
   │
   ▼
[useEffect の setInterval がループ起動（例: 125ms ごと）]
   │
   ├── [125ms 後] tick = 1 ➔ triggerStepSounds(1) ➔ 画面ヘッドが Step 1 へ移動
   ├── [250ms 後] tick = 2 ➔ triggerStepSounds(2) ➔ 画面ヘッドが Step 2 へ移動
   │   ...（BPMの速度で刻み続ける）...
   └── ループ終端に達したら 0 へ戻り、シームレスに永久ループ再生

--------------------------------------------------------------------------------
【フロー B: 2小節から4小節へ拡張したとき】
--------------------------------------------------------------------------------
[ユーザーがループセレクタの「4小節」をクリック]
   │
   ▼
[handleMeasureChange(4) が呼ばれる（oldBars = 2）]
   │
   ├──▶ newBars (4) > oldBars (2) を検知
   ├──▶ expandPatternMeasures(pattern, 2, 4, 16) が実行される
   │     ・1小節目（Bar 0）のデータ ➔ 3小節目（Bar 2）へまるごとコピー
   │     ・2小節目（Bar 1）のデータ ➔ 4小節目（Bar 3）へまるごとコピー
   ├──▶ setPattern(...) で 4小節分のパターンが確定
   ├──▶ 全体長（32ステップ）だったトラック長を 64ステップへ延伸
   └──▶ setBars(4) ➔ 画面の編集小節ボタンが「Bar 1〜4」に広がり、即座に編集可能に！

--------------------------------------------------------------------------------
【フロー C: WAV または MIDI ファイルを書き出すとき】
--------------------------------------------------------------------------------
[ユーザーが「書き出し ▼」➔「WAV オーディオ」をクリック]
   │
   ▼
[ExportMenu の handleExportWav() が呼ばれる]
   │
   ├──▶ isExportingWav = true ➔ ボタンが「レンダリング中...」スピナーに変化
   ├──▶ renderPatternToWavBlob(...) が実行される
   │     ・OfflineAudioContext が裏で起動
   │     ・全小節の音声を数十ミリ秒で超高速オフライン計算
   │     ・最後のシンバル余韻（1.5秒）も含めた 16-bit PCM WAV バイナリを作成
   ├──▶ downloadBlob(blob, "rhythm-4_4-120bpm-4bars-....wav")
